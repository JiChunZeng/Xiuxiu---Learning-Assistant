# 给你的报告

在这个仓库的对话里说「同步」。助手先拉取，再读 `她做的/学习记录/` 里的新文件，按下面的格式写，并更新 `跟踪/进度表.md`。不要修改 `她做的/`。

换到别的对话时，把本文件和记录一起贴过去。

共同规则：

- 记录里没有的事不要写成已经发生。
- 没收到记录：进度表记「没有记录」，不要补她的代码。
- 陪练代写了完整答案：该天记「有」，下一步是她不看答案重打那个文件。
- 卡住、代写、情绪是「烦」或「想停」：明确写明天留在原任务。
- 用时超过 70 分钟：提醒把她按回 60 分钟以内。
- 「建议回她」写成哥哥能说的短句，具体到她今天做成的那一下。发给她之前用你自己的口气改。

## 出日报

原始记录就是 `她做的/学习记录/` 里的文件，不要再抄一份。更新进度表那一行：动作、完成、分钟、代写、情绪、备注。动作列填做了或没做。

```
# 日报 {日期}

结论：明天做第_周第_天 / 明天仍留在第_周第_天
完成情况：
用时：
程序员动作：
找资料：
她是否自己打的代码：
陪练有没有代写：
卡住：
情绪：
你要做的一件事：
建议回她：
```

「你要做的一件事」大多数日子是：用自己的话回她一句。第 7 天改为：把她发来的 `.py` 放进 `code/` 并提交。

## 出周报

把这一周能找到的学习记录和进度表行看完再写。

```
# 周报 第{N}周 {起止}

本周目标：
做了几天（含休息）：
没有记录的日子：
真正会了的：
这周的程序员动作：做了 / 没稳住
还要停留的：
大纲：往前进入下一周 / 停留在第_周第_天
你这周要补的一件事：
建议回她：
```

若这一周已经是第 4、8 或 12 周，写完周报后接着按月报格式再写一份。

程序员动作没稳住时，大纲写停留，不要写往前。只有在「大纲：往前」时，才根据 `大纲.md` 写出下一周 7 条提示词，格式与 `给她/每日提示词.md` 相同，每天只增加一个新东西，并且只带大纲里那一周的一件程序员动作。停留时，下一周 7 天都是原任务的小变体，不出现大纲里的下一个新概念。写出的提示词追加到 `给她/每日提示词.md`，并在进度表接上 7 行。

## 出月报

```
# 月报 第{N}月 {起止}

她能独立做的：
需求和找资料哪件已经能自己做：
还不稳定的：
耗时和情绪：
阶段结论：进入下一阶段 / 下一月用来补{哪一项}
下月只盯的一个能力：
需要你出面的事：
```

第 1 月对应阶段 A，第 2 月对应阶段 B，第 3 月对应阶段 C。
