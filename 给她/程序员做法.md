# 程序员做法

做一个日常小工具，按下面的顺序来。每天只练提示词里写的那一件「程序员动作」，最多 8 分钟。只有半小时时，动作收成一句「怎样算做完」。

Python 是把工具写出来的第一支笔。以后换成别的语言，这个顺序不变。

## 顺序

1. 用一句话说清要解决的小事。
2. 写下一句「怎样算做完」。
3. 自己拿一个具体例子算一遍，把结果记下来。
4. 换一个新工具时，先写六行需求。
5. 设计成三步：输入、处理、输出。先把能跑的第一步做出来。
6. 报错就读终端最后一行，一次只改一处，再用同一个例子跑。
7. 对照「怎样算做完」。没做到就改程序，不把需求改松来凑。

## 六行需求

一个新工具对应一个 md 文件，只写这六行。

```
# 工具名
给谁用：
解决的小事：
输入：
输出：
这次不做：
怎样算做完：
```

## 怎么找资料

1. 先读终端最后一行。
2. 搜索词自己打：那一行里最短的英文，后面加上 `python`。
3. 只打开一条结果。地址里有 `docs.python.org` 的那条优先。
4. 用自己的话说看懂的一句，写进笔记。看不懂就关掉，回到程序里改一处。
5. 问 Cursor 或问哥哥时带上三样：最后一行报错、你期望的结果、实际的结果。

## 工具一个一个认

1. Cursor 里的文件
2. 终端
3. 浏览器搜索
4. 需求 md
5. 文件夹：需求、代码、学习记录分开
6. Python 官方文档里的一页
7. GitHub 网页上的提交记录（只看）

这学期不换第二套编辑器，不同时开第二门语言。数据库和 Java 放到能按六行需求独立做完一个小工具之后。
